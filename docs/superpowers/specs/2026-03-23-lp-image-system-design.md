# LP Image System — Design Spec

## Overview

Add image support to the LP generator, giving users full control over images in their landing pages through 3 sources: **upload**, **stock photos (Pexels)**, and **AI-generated (Google Imagen)**. Users can also opt out of images entirely (CSS-only mode, current behavior).

## Image Slots

- **Hero** (required if using images)
- **Second fold** (optional, only available if hero has an image)
- **No-images mode** — CSS-only design, identical to current behavior

## Image Sources

### 1. Upload
User uploads their own image. Two modes:
- **"Use this image"** — embedded directly in the LP
- **"Use as inspiration"** — app analyzes mood, style, colors, subject matter to guide stock search and AI generation prompts

### 2. Stock Photo (Pexels API)
- Free, no attribution required for commercial use
- 200 requests/hour
- Search queries generated by Claude Haiku based on the brief + inspiration image
- English search queries (Haiku translates from Hebrew brief)
- Focus on Mediterranean aesthetic, warm tones, authentic-looking people

### 3. AI Generated (Google Imagen)
- ~$0.02-0.04 per image
- ~5-8 seconds generation time
- Prompts generated by Claude Haiku based on the brief + inspiration image

## User Flow

### Phase 1: Creation (new.html)

New Step 7 added to the questionnaire:

1. User chooses: **"With images"** or **"No images (CSS only)"**
2. If with images:
   - **Hero image**: upload zone with drag & drop
     - After upload: choice between "Use this exact image" / "Use as inspiration"
     - Explanation text: "Inspiration means we'll analyze the mood, style & colors to find or generate a similar image for you"
     - Or skip — system auto-finds images based on brief
   - **Second fold image**: off-by-default toggle. When on, same upload zone appears
3. Submit creates project with `image_mode` and optional upload URLs

Works in both Questionnaire mode and Brief mode.

### Phase 2: Generation (generate-lp.js)

When user clicks "Generate" in dashboard:

**If `image_mode = "css_only"`:** Same as today. No change.

**If `image_mode = "with_images"`:**

1. **Image Resolution Pipeline** runs first (new `resolve-images.js`):
   - For each slot (hero, fold2 if enabled):
     - If "use directly" upload exists → use URL as-is
     - If "inspiration" upload or no upload:
       - Haiku analyzes brief + inspiration image
       - Generates Pexels search query + Imagen prompt
       - Pexels search + Imagen generation run **in parallel**
       - Auto-picks best result (Pexels top result or Imagen output)
2. **Claude Opus generates LP:**
   - Receives: text brief + **resolved image URLs** + inspiration image (multimodal, if exists)
   - Prompt updated with image placement rules
   - Generates HTML with `data-image-slot="hero"` and `data-image-slot="fold2"` attributes
   - Designs layout, colors, typography to complement the actual images
3. Save HTML to `project_variants.generated_html`
4. Save image URLs to `lp_image_content` table
5. Extract `data-editable` keys (existing behavior)

### Phase 3: Post-Generation Editing (dashboard)

User previews LP in dashboard iframe. Existing text editing unchanged.

**Image swapping (new):**
1. User hovers on image → "Change Image" overlay appears with slot label
2. Click → Image Picker modal opens with 3 tabs:
   - **Upload tab**: drag & drop → immediate swap
   - **Stock Photo tab**: 3 Haiku-generated visual directions (based on brief) → pick direction → browse Pexels grid → select → apply
   - **AI Generated tab**: same 3 directions → pick direction → generate one image (~5-8s) → apply or "Generate Another Variation"
3. New URL saved to `lp_image_content` — no LP regeneration needed
4. Layout stays as-is when swapping (v1). User responsible for picking images that fit.

**The 3 directions** are visual interpretations of the brief, e.g.:
- "Warm candlelit gathering, intimate mood"
- "Mediterranean garden, golden hour circle"
- "Woman contemplating, morning light & books"

Shared across Stock and AI tabs. Only shown when user actively wants to swap (not part of default flow).

### Phase 4: Serving (serve-lp.js)

Updated flow:
1. Fetch project by slug (existing)
2. Fetch published variant HTML (existing)
3. Fetch text overrides from `lp_editable_content` (existing)
4. **Fetch image overrides from `lp_image_content`** (new)
5. Apply text overrides via regex (existing)
6. **Apply image overrides** (new): find `data-image-slot="X"` → replace `src` with override URL
7. Inject analytics script (existing)
8. Serve HTML with cache headers (existing)

## Data Model

### New Table: `lp_image_content`

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID (PK) | Primary key |
| project_id | UUID (FK → projects) | Which project |
| variant_id | UUID (FK → project_variants, nullable) | Which variant (A/B support) |
| slot | TEXT | "hero" or "fold2" |
| image_url | TEXT | Current image URL (swappable) |
| source | TEXT | "upload" / "pexels" / "imagen" |
| source_meta | JSONB | Pexels photo ID, Imagen prompt, attribution, etc. |
| created_at | TIMESTAMPTZ | When set/swapped |

**Constraint:** UNIQUE(variant_id, slot)

### Modified Table: `projects`

| New Column | Type | Purpose |
|------------|------|---------|
| image_mode | TEXT | "with_images" / "css_only" |
| inspiration_image_url | TEXT (nullable) | Upload marked as "inspiration" (separate from existing `image_url` for "use directly") |

Existing `image_url` column keeps its role for "use directly" uploads.

### Supabase Storage: `lp-images` bucket

New folder structure:
```
lp-images/
  uploads/        ← existing user uploads (direct use)
  inspiration/    ← NEW: reference images
  generated/      ← NEW: AI-generated images (saved from Imagen)
```

Pexels images served directly from Pexels CDN — not stored.
Imagen results saved to storage (we own them).

## Claude Prompt Changes

### CSS-Only Mode
Identical to current prompt. No change.

### With-Images Mode

New instructions added to system prompt:
```
IMAGE PLACEMENT RULES:
- You have been provided with real image URLs. Use them.
- Hero section MUST include the hero image using:
    <img data-image-slot="hero" src="{hero_url}" ...>
- If a second fold image URL is provided, include it using:
    <img data-image-slot="fold2" src="{fold2_url}" ...>
- Design the color palette, typography, and mood to COMPLEMENT the provided images.
- Images should be responsive: width:100%, height:auto
- Use object-fit:cover for hero images
- Add appropriate alt text based on the brief context
- Hero image can be used as: full background, partial overlay, side-by-side with text, or contained block
- The data-image-slot attribute is REQUIRED for swapping
```

User message includes:
- Text brief (existing, unchanged)
- Resolved image URLs with source info
- Inspiration image as multimodal block (if exists, same as today)

## API Endpoints

### New: `/api/resolve-images.js`
- **Input:** `{ project_id, access_token }`
- **Process:** Haiku analysis → Pexels + Imagen in parallel → return resolved URLs
- **Output:** `{ hero: { url, source, meta }, fold2: { url, source, meta } }`

### New: `/api/image-directions.js`
- **Input:** `{ project_id, access_token }`
- **Process:** Haiku generates 3 visual directions from brief + inspiration
- **Output:** `{ directions: ["description1", "description2", "description3"] }`

### New: `/api/swap-image.js`
- **Input:** `{ project_id, variant_id, slot, source_type, direction?, access_token }`
- **Process:**
  - If source_type = "pexels": search with direction as query → return results grid
  - If source_type = "imagen": generate image from direction prompt → return URL
  - If source_type = "upload": save uploaded URL
- **Output:** `{ results: [...] }` (stock) or `{ url, source_meta }` (AI/upload)

### Modified: `/api/generate-lp.js`
- Calls `resolve-images` first if `image_mode = "with_images"`
- Passes resolved URLs to Claude prompt
- Saves image data to `lp_image_content` after generation

### Modified: `/api/serve-lp.js`
- Fetches image overrides from `lp_image_content`
- Replaces `src` on `data-image-slot` elements via regex

| new.html | Step 7: image mode toggle + upload with direct/inspiration | Medium |
| api/resolve-images.js | New: Haiku → Pexels + Imagen pipeline | Large |
| api/image-directions.js | New: 3 visual directions from Haiku | Small |
| api/swap-image.js | New: fetch stock / generate AI for a direction | Medium |
| api/generate-lp.js | Modified: orchestrate image pipeline + updated prompt | Medium |

## Costs Per LP Generation

| Service | When | Cost |
|---------|------|------|
| Haiku (image analysis) | Every "with_images" generation | ~$0.001 |
| Pexels API | Every auto-pick + every stock swap | Free |
| Google Imagen | Every auto-pick + every AI swap | ~$0.02-0.04/image |
| Claude Opus (LP generation) | Every generation | Existing cost, unchanged |

## Backwards Compatibility

- CSS-only mode is identical to current behavior
- No existing LPs break
- `image_mode` defaults to "css_only" for existing projects
- The image system is purely additive
