# LP Image System — Design Spec

## Overview

Add image support to the LP generator, giving users full control over images in their landing pages through 3 sources: **upload**, **stock photos (Pexels)**, and **AI-generated (Google Imagen)**. Users can also opt out of images entirely (CSS-only mode).

## Image Slots

- **Hero** (required if using images)
- **Second fold** (optional, only available if hero has an image)
- **No-images mode** — CSS-only design

## Image Sources

### 1. Upload
User uploads their own image. Two modes:
- **"Use this image"** — embedded directly in the LP
- **"Use as inspiration"** — app analyzes mood, style, colors, subject matter to guide stock search and AI generation prompts

### 2. Stock Photo (Pexels API)
- Free, no attribution required for commercial use
- 200 requests/hour
- Search queries generated by Claude Haiku based on the brief + inspiration image
- English search queries (Haiku translates from Hebrew brief)
- Focus on Mediterranean aesthetic, warm tones, authentic-looking people
- Request landscape orientation for hero, portrait/square for fold2

### 3. AI Generated (Google Imagen)
- ~$0.02-0.04 per image
- ~5-8 seconds generation time
- Prompts generated by Claude Haiku based on the brief + inspiration image
- Request 16:9 aspect ratio for hero, 4:3 for fold2

## Auto-Pick Algorithm

When the image resolution pipeline runs automatically (no user upload or "inspiration" upload), it needs to choose an image:

1. Haiku generates a Pexels search query + Imagen prompt (one call, both outputs)
2. Pexels search + Imagen generation run in **parallel**
3. **Selection logic:** Prefer Pexels top result (free). Fall back to Imagen only if Pexels returns 0 results.
4. Selected image URL is cached to Supabase Storage (see Image Caching below) before passing to Claude.

## Error Handling & Fallbacks

| Failure | Behavior |
|---------|----------|
| Pexels returns 0 results | Use Imagen result |
| Imagen fails (content policy, timeout) | Use Pexels top result |
| Both Pexels and Imagen fail | Fall back to CSS-only for that slot. If hero slot fails, entire LP generates as CSS-only. |
| Pexels rate limit (200/hr) hit | Use Imagen result, log warning |
| Inspiration image upload is corrupted/inaccessible | Skip inspiration analysis, generate based on text brief only |
| Haiku analysis fails | Use hardcoded fallback search query derived from business name + "professional background" |

## User Flow

### Phase 1: Creation (new.html)

New step added to the questionnaire (inserted as Step 6, before Email Settings which becomes Step 7):

1. User chooses: **"With images"** or **"No images (CSS only)"**
2. If with images:
   - **Hero image**: upload zone with drag & drop
     - After upload: choice between "Use this exact image" / "Use as inspiration"
     - Explanation text: "Inspiration means we'll analyze the mood, style & colors to find or generate a matching image for you"
     - Or skip — system auto-finds images based on brief
   - **Second fold image**: off-by-default toggle. When on, same upload zone appears
3. Submit creates project with `image_mode` and optional upload URLs

**Questionnaire mode:** New step in the wizard.
**Brief mode:** New section below the existing text area + image upload, with the same toggle and upload zones.

**Note on current validation:** The existing form requires an image upload (used as inspiration for CSS design). With the new `image_mode` field:
- `"with_images"` — upload is optional (system auto-finds if skipped)
- `"css_only"` — upload is optional (used for color/mood inspiration if provided, same as current behavior)

### Phase 2: Generation

When user clicks "Generate" in dashboard, the client orchestrates two sequential calls:

**If `image_mode = "css_only"`:** Client calls `generate-lp` directly. Prompt unchanged — same behavior as today.

**If `image_mode = "with_images"`:**

**Step A — Client calls `/api/resolve-images`** (separate HTTP call):
- Dashboard shows "Finding images..." progress state
- For each slot (hero, fold2 if enabled):
  - If "use directly" upload exists → use URL as-is
  - If "inspiration" upload or no upload → Haiku analyzes brief + inspiration → Pexels + Imagen in parallel → auto-pick per algorithm above
- Returns resolved image URLs to the client

**Step B — Client calls `/api/generate-lp`** with resolved image URLs:
- Dashboard shows "Generating page..." progress state
- Claude Opus receives: text brief + resolved image URLs + inspiration image (multimodal, if exists)
- Prompt includes image placement rules (with-images mode)
- Generates HTML with `data-image-slot="hero"` and `data-image-slot="fold2"` attributes
- Designs layout, colors, typography to complement the actual images
- Save HTML to `project_variants.generated_html` AND `projects.generated_html` (backward compat)
- Save image URLs to `lp_image_content` table
- Extract `data-editable` keys (existing behavior)

**Why two separate calls:** Avoids Vercel serverless timeout risk. Image resolution (Haiku + Pexels + Imagen) can take 5-10s, and LP generation takes 30-60s. Chaining them in one function risks exceeding the 60s timeout. Splitting also gives the UI natural progress states.

### Phase 3: Post-Generation Editing (dashboard)

User previews LP in dashboard iframe. Existing text editing unchanged.

**Image swapping (new):**
1. User hovers on image → "Change Image" overlay appears with slot label
2. Click → Image Picker modal opens with 3 tabs:
   - **Upload tab**: drag & drop → immediate swap
   - **Stock Photo tab**: 3 Haiku-generated visual directions (based on brief) → pick direction → browse Pexels grid → select → apply
   - **AI Generated tab**: same 3 directions → pick direction → generate one image (~5-8s) → apply or "Generate Another Variation"
3. New URL saved to `lp_image_content` — no LP regeneration needed
4. Layout stays as-is when swapping (v1). User responsible for picking images that fit.

**The 3 directions** are visual interpretations of the brief, e.g.:
- "Warm candlelit gathering, intimate mood"
- "Mediterranean garden, golden hour circle"
- "Woman contemplating, morning light & books"

Shared across Stock and AI tabs. Only shown when user actively wants to swap (not part of default flow).

### Phase 4: Serving (serve-lp.js)

Updated flow:
1. Fetch project by slug (existing)
2. Fetch published variant HTML (existing)
3. Fetch text overrides from `lp_editable_content` (existing)
4. **Fetch image overrides from `lp_image_content`** (new)
5. Apply text overrides via regex (existing)
6. **Apply image overrides** (new): find `data-image-slot="X"` → replace `src` with override URL (see Image Override Regex below)
7. Inject analytics script (existing)
8. Serve HTML with cache headers (existing)

**Image Override Regex:** Use a robust regex that handles attribute ordering:
```
// Match any <img> tag containing data-image-slot="hero", regardless of attribute order
const regex = /(<img\b[^>]*data-image-slot="hero"[^>]*\bsrc=")([^"]*)(")/;
// Also handle case where src comes before data-image-slot
const regex2 = /(<img\b[^>]*\bsrc=")([^"]*)("[^>]*data-image-slot="hero")/;
```

## Data Model

### New Table: `lp_image_content`

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID (PK) | Primary key |
| project_id | UUID (FK → projects) | Which project |
| variant_id | UUID (FK → project_variants) | Which variant — NOT NULL, uses default variant |
| slot | TEXT | "hero" or "fold2" |
| image_url | TEXT | Current image URL (always a cached Supabase Storage URL) |
| source | TEXT | "upload" / "pexels" / "imagen" |
| source_meta | JSONB | Pexels photo ID, Imagen prompt, original external URL, attribution, etc. |
| created_at | TIMESTAMPTZ | When set/swapped |

**Constraint:** UNIQUE(variant_id, slot)

**Note:** `variant_id` is NOT NULL. Every project has a default variant (existing behavior). This avoids NULL uniqueness issues in PostgreSQL.

**RLS Policies:**
- SELECT: users can read their own project images (via project ownership check) + managers can read all
- INSERT/UPDATE/DELETE: users can modify their own project images + managers can modify all
- Pattern matches existing `lp_editable_content` RLS policies

### Modified Table: `projects`

| New Column | Type | Purpose |
|------------|------|---------|
| image_mode | TEXT DEFAULT 'css_only' | "with_images" / "css_only" |

**Note on `image_url` column:** The existing `image_url` column currently stores inspiration images (used for color palette and mood reference in generation). This role is unchanged. In the new flow:
- `image_url` continues to store the inspiration/reference image (uploaded in creation form)
- For "use directly" uploads, the URL goes directly into `lp_image_content` for the relevant slot
- No new `inspiration_image_url` column needed — `image_url` already serves this purpose

**Migration for existing projects:** All existing projects get `image_mode = 'css_only'` (default). No data migration needed.

### Supabase Storage: `lp-images` bucket

New folder structure:
```
lp-images/
  uploads/        ← existing user uploads (inspiration/direct use)
  generated/      ← NEW: AI-generated images (saved from Imagen)
  cached/         ← NEW: Cached copies of Pexels images
```

### Image Caching

All images used in LPs are cached to Supabase Storage before being saved to `lp_image_content`:
- **Uploads:** already in Supabase Storage
- **Pexels:** fetched from Pexels CDN and saved to `lp-images/cached/{pexels_photo_id}.jpg`
- **Imagen:** saved to `lp-images/generated/{timestamp}_{random}.png`

`lp_image_content.image_url` always points to Supabase Storage, never to external CDNs. This prevents broken images if Pexels removes a photo.

`source_meta` stores the original external URL and attribution info for reference.

## Claude Prompt Changes

### CSS-Only Mode
Identical to current prompt. No change. The existing rule "Do NOT use any external images or placeholder image URLs" remains.

### With-Images Mode
The "no images" rule (rule 11 in current system prompt) is **replaced** with:

```
IMAGE PLACEMENT RULES:
- You have been provided with real image URLs. Use them.
- Hero section MUST include the hero image using:
    <img data-image-slot="hero" src="{hero_url}" ...>
- If a second fold image URL is provided, include it using:
    <img data-image-slot="fold2" src="{fold2_url}" ...>
- Design the color palette, typography, and mood to COMPLEMENT the provided images.
- Images should be responsive: width:100%, height:auto
- Use object-fit:cover for hero images
- Add appropriate alt text based on the brief context
- Hero image can be used as: full background, partial overlay, side-by-side with text, or contained block
- The data-image-slot attribute is REQUIRED for swapping
- Do NOT add any other <img> tags beyond the provided slots
```

User message includes:
- Text brief (existing, unchanged)
- Resolved image URLs with source info
- Inspiration image as multimodal block (if exists, same as today)

## API Endpoints

### New: `/api/resolve-images.js`
- **Input:** `{ project_id, access_token }`
- **Process:** Haiku analysis → Pexels + Imagen in parallel → auto-pick → cache to storage → return URLs
- **Output:** `{ hero: { url, source, meta }, fold2: { url, source, meta } | null }`
- **Called by:** Dashboard client (separate call before generate-lp)

### New: `/api/image-directions.js`
- **Input:** `{ project_id, access_token }`
- **Process:** Haiku generates 3 visual directions from brief + inspiration
- **Output:** `{ directions: ["description1", "description2", "description3"] }`
- **Called by:** Dashboard client when user opens image swap modal

### New: `/api/search-images.js`
- **Input:** `{ direction, source_type, access_token }`
- **Process:**
  - If source_type = "pexels": search Pexels with direction as query → return results grid
  - If source_type = "imagen": generate image from direction as prompt → cache to storage → return URL
- **Output:** `{ results: [{ url, thumbnail_url, source_meta }] }` (pexels) or `{ results: [{ url, source_meta }] }` (imagen)
- **Called by:** Dashboard client when user picks a direction in swap modal

### New: `/api/apply-image.js`
- **Input:** `{ project_id, variant_id, slot, image_url, source, source_meta, access_token }`
- **Process:** Cache image to storage (if not already cached) → upsert into `lp_image_content`
- **Output:** `{ success: true, cached_url }`
- **Called by:** Dashboard client when user confirms image selection

### Modified: `/api/generate-lp.js`
- Accepts optional `resolved_images` parameter with pre-resolved image URLs
- If `image_mode = "with_images"` and `resolved_images` provided: uses them in prompt
- If `image_mode = "with_images"` and no `resolved_images`: calls resolve-images internally as fallback
- Saves image data to `lp_image_content` after generation
- Updated prompt: conditionally includes image rules or CSS-only rules based on `image_mode`
- Continues to save to both `project_variants.generated_html` AND `projects.generated_html` (backward compat)

### Modified: `/api/serve-lp.js`
- Fetches image overrides from `lp_image_content`
- Replaces `src` on `data-image-slot` elements via robust regex (handles attribute ordering)

## Regeneration Behavior

When a user clicks "Generate" again on a project that already has images:

- Image resolution pipeline runs again with fresh results
- New images are saved to `lp_image_content`, overwriting previous entries
- Previous manual swaps are lost
- Dashboard should show a confirmation: "Regenerating will replace your current images. Continue?"

## A/B Variant Behavior

When user creates a new variant (A/B test):
- Images from the default variant are **copied** to the new variant's `lp_image_content` rows
- Each variant can then have its images swapped independently
- This matches how `generated_html` is already duplicated per variant

## Implementation Components

| Component | Change | Effort |
|-----------|--------|--------|
| DB Migration | New `lp_image_content` table with RLS + `projects.image_mode` column | Small |
| new.html | New step: image mode toggle + upload with direct/inspiration | Medium |
| api/resolve-images.js | New: Haiku → Pexels + Imagen pipeline with auto-pick + caching | Large |
| api/image-directions.js | New: 3 visual directions from Haiku | Small |
| api/search-images.js | New: search Pexels or generate Imagen for a direction | Medium |
| api/apply-image.js | New: cache image + upsert lp_image_content | Small |
| api/generate-lp.js | Modified: accept resolved_images, updated prompt (conditional) | Medium |
| api/serve-lp.js | Modified: image URL replacement at serve time | Small |
| dashboard.html | Image hover overlay + Image Picker modal (3 tabs) + progress states | Large |

## Costs Per LP Generation

| Service | When | Cost |
|---------|------|------|
| Haiku (image analysis) | Every "with_images" generation | ~$0.001 |
| Pexels API | Every auto-pick + every stock swap | Free |
| Google Imagen | Fallback auto-pick + every AI swap | ~$0.02-0.04/image |
| Supabase Storage | Cached images | Negligible (within free tier) |
| Claude Opus (LP generation) | Every generation | Existing cost, unchanged |

## Backwards Compatibility

- Existing projects get `image_mode = 'css_only'` by default
- No existing LPs break — `serve-lp` only swaps images if `lp_image_content` rows exist
- The existing `image_url` column retains its current role (inspiration image)
- The "no images" rule in the prompt is only replaced when `image_mode = "with_images"`
- Current image upload validation in the form is relaxed: upload becomes optional in both modes
